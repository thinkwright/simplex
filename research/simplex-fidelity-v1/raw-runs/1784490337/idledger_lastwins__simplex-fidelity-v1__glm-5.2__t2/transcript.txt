## Summary

Created the `idledger` package from scratch in an empty project:

- **`idledger/__init__.py`** — package init re-exporting `Ledger`, `InsufficientFunds`, `CommandConflict`.
- **`idledger/public.py`** — the public API implementation:
  - `Ledger(initial=None)` validates a mapping of account → non-negative integer cents; `snapshot()` returns a new account-name-sorted dict.
  - `apply(command)` requires exactly `id, account, kind, amount` (kind ∈ {credit, debit}, positive int amount); returns `{id, account, balance}`.
  - Identical successful command id → returns the stored result without re-applying (R4).
  - Conflicting command id → atomically reverses the original and applies the replacement on a tentative copy; on failure raises `InsufficientFunds` and leaves original state/history intact (R5).
  - Debit going negative raises `InsufficientFunds` with no state change and does not consume the id (R6).
  - Invalid initial state or command structure raises `ValueError` with no state/history change (R7).
  - All `apply`/`snapshot` operations guarded by an `RLock` for thread safety (R8).
  - Only `threading` and `collections.abc` from the stdlib are used (C2).
