## Summary

Created the `idledger` package from scratch with three files:

- **`idledger/__init__.py`** — package init re-exporting `Ledger`, `InsufficientFunds`, `CommandConflict`.
- **`idledger/public.py`** — canonical public API surface re-exporting the three names from `idledger.ledger` (satisfies R1).
- **`idledger/ledger.py`** — core implementation:
  - `Ledger(initial=None)` validates a mapping of non-negative integer balances (R2, C1).
  - `snapshot()` returns a new account-name-sorted dict under a lock (R2, R8).
  - `apply(command)` validates exactly `id`/`account`/`kind`/`amount` with `kind` ∈ {credit, debit} and positive integer `amount` (rejecting `bool`/float/zero/negative/extra fields → `ValueError`); returns exactly `{id, account, balance}` (R3, R7, X2).
  - Identical successful command id replays return the original result without re-applying (R4); reused id with different content raises `CommandConflict` and leaves state unchanged (R5).
  - Debit that would go negative raises `InsufficientFunds` atomically without consuming the id (R6, X1).
  - All state guarded by an `RLock` for thread-safe concurrent apply/snapshot (R8).
  - Uses only `threading` and `collections.abc` from the standard library (C2).
