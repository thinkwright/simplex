**Summary**

Created the `idledger` package with three files:

- `idledger/__init__.py` — re-exports `Ledger`, `InsufficientFunds`, `CommandConflict` from `idledger.public`.
- `idledger/public.py` — public API surface.
- `idledger/ledger.py` — implementation using only `threading` from the stdlib.

**Key design points**
- `Ledger(initial=None)` validates the initial mapping (non-negative ints, no bools) before storing; `snapshot()` returns a sorted copy under the lock.
- `apply(command)` validates the command (exactly `id`, `account`, `kind`, `amount`; positive int amount; `credit`/`debit` kind) **before** acquiring the lock, so invalid commands leave state and history untouched.
- Idempotency: a `cid` already in history returns the original result if content matches, or raises `CommandConflict` if it differs — without mutating balances.
- `InsufficientFunds` is raised before any mutation and the command id is **not** recorded, so it remains reusable.
- A single `threading.Lock` guards both balance updates and history, so concurrent distinct credits each apply exactly once.
