## Summary

I implemented the `tokenquota` package with two files:

- **`tokenquota/public.py`** — defines and exposes `Bucket(capacity, refill_per_second, clock=None)`.
- **`tokenquota/__init__.py`** — re-exports `Bucket` for convenience.

### Key implementation decisions
- **Clock (C1/R3):** Only `self._clock()` is used for elapsed-time decisions; it defaults to `time.monotonic` when none is supplied. Backward clock movement is treated as zero elapsed time and does **not** reset the reference point (`_last` only advances on positive elapsed time), so negative movement can never grant tokens — directly or indirectly.
- **Refill (R3):** `balance += elapsed * refill_per_second`, clamped to `capacity`.
- **Rounding (R4/R5):** The underlying balance is kept at full precision between operations (so fractional accrual is never lost — a rate-0.5 bucket polled every second still accumulates). The balance is rounded down with `math.floor` *before answering*: `available()` returns `floor(balance)`, and `allow()` decides on `floor(balance) >= amount`. This satisfies E2 (`available() == 1` from 1.5) while keeping the rate limiter correct.
- **Validation (R6/X1):** `capacity > 0`, `refill_per_second >= 0`, and `amount > 0` and not a `bool`; non-numeric values are rejected too. All raise `ValueError`, and `allow` validates before acquiring the lock, so invalid amounts never consume tokens.
- **Thread-safety (R7):** A `threading.Lock` serializes the refill+check+consume in both `allow` and `available`.
- **Dependencies (E6/C1):** Only `math`, `threading`, `time` (all standard library) are imported.
